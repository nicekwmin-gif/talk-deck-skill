# 자료 모으기: 사용자에게 요구할 것과 에이전트가 수집할 것

원칙: **사용자만 가진 것은 처음에 한 번에 요구하고, 그 밖의 것은 에이전트가 찾아온다.** 사용자에게 "배경 자료를 달라", "사진을 달라"고 떠넘기지 않는다. 대신 찾아온 것은 출처와 함께 보여 주고 쓸지 말지 확인받는다.

## 1. 사용자에게 요구할 것 (에이전트가 구할 수 없는 것)

스토리라인을 쓰기 전에 아래 목록을 한 번에 보낸다. 받은 것과 못 받은 것을 표로 정리해 둔다.

| 요구할 것 | 형식 | 없으면 |
|---|---|---|
| 핵심 데이터 (보여 줄 결과) | 엑셀·CSV 원자료가 가장 좋다. 없으면 그림 파일, 보고서 PDF | 진행 불가. 반드시 받는다 |
| 제품·서비스·연구의 정확한 설명 | 사양서, 소개서, 원고, 이전 발표 자료 | 사용자에게 5문장으로 설명해 달라고 한다 |
| 청중 정보 | 회사·부서·직급, 무엇을 결정하는 자리인가, 이미 아는 것 | 반드시 받는다 |
| 발표 뒤 청중이 하길 바라는 행동 | 한 문장 | 반드시 받는다 |
| 발표 시간·날짜·장소·화면 비율 | | 15분, 16:9로 가정하고 알린다 |
| 자기 사진 (제품, 현장, 장비, 사람) | 원본 해상도 파일, 촬영자·날짜 | 사진 없는 구성으로 간다 |
| 로고, 회사 템플릿(pptx/potx), 브랜드 색 | 파일 | 기본 디자인 체계로 간다 |
| 공개하면 안 되는 것 | 수치, 고객사 이름, 가격, 미공개 내용 목록 | 불확실한 것은 넣지 않는다 |
| 꼭 넣어야 하는 것 / 빼야 하는 것 | 목록 | |
| 마음에 들었던 발표 자료 예시 | 파일이나 화면 캡처 1–2개 | 없어도 된다 |

- 작업 폴더에 이미 있는 파일은 요구하지 않는다. 먼저 폴더를 훑고, 찾은 것을 "이걸 쓰면 되나요?"로 확인한다.
- 한 번에 묻는다. 작업 중에 새로 필요한 것이 생기면 모아서 다시 한 번에 묻는다.

## 2. 에이전트가 수집할 것

| 수집할 것 | 어디서 | 기록 |
|---|---|---|
| 배경 사실·통계 (시장 규모, 현황, 규제, 기준값) | 정부·공공기관 통계, 국제기구 보고서, 학술 논문, 표준 문서 | `_tmp/factsheet.md`에 주장 · 수치 · 출처 URL · 확인 방법 |
| 선행 연구·비교 대상의 수치 | 논문 초록·본문을 직접 연다 | 같음. 초록만 봤는지 본문을 봤는지 구분 |
| 배경 사진·도해 | 아래 3절의 공개 자료 | `assets/SOURCES.md`에 파일 · 원본 URL · 저작자 · 라이선스 · 받은 날짜 |
| 사용자의 이전 덱·보고서 속 그림 | 작업 폴더, 사용자가 알려 준 폴더. pptx는 `ppt/media/`에서 뽑는다 | SOURCES.md에 어느 파일 몇 번째 장인지 |
| 사용자 데이터로 다시 그린 그래프 | 받은 원자료 | 그리는 스크립트를 `scripts/`에 남긴다 |

수집 규칙:
- **웹 검색 도구가 있으면 쓴다. 없으면** 필요한 자료 목록(무엇을, 왜, 어떤 조건으로)을 만들어 사용자에게 넘기고, 그 부분은 `[확인]`으로 비워 둔다. 기억으로 수치를 채우지 않는다.
- 수치는 **1차 출처**에서 확인한다. 보도자료·블로그·위키만 본 경우 factsheet에 "보도자료뿐"이라고 적고 슬라이드에는 쓰지 않거나 사용자에게 알린다.
- 출처마다 수치가 다르면 둘 다 적고 어느 것을 쓸지 사용자가 고르게 한다.
- 수집한 사실은 여러 건을 조사한 뒤 한 번에 표로 보고한다. 조사 범위가 넓으면 주제별로 나눠(하위 에이전트를 쓸 수 있으면 주제마다 하나씩) 조사한다.
- 사용자 회사·제품 이름, 미공개 내용을 검색어나 외부 서비스 입력에 넣지 않는다.

## 3. 사진·그림 수집

쓸 수 있는 곳 (라이선스를 **그 파일의 페이지에서** 확인한다):

| 출처 | 보통의 조건 |
|---|---|
| 정부·공공기관 공개 이미지 (예: NASA, NOAA, USGS, 공공누리 1유형) | 출처 표시 후 사용 가능. 기관마다 예외가 있으니 이미지별 조건 확인 |
| Wikimedia Commons | 파일마다 다르다. CC BY / CC BY-SA면 저작자·라이선스 표시 |
| Unsplash, Pexels 같은 무료 스톡 | 사용 가능하나, 내용과 딱 맞을 때만 쓴다. 분위기용 스톡 사진은 넣지 않는다 |
| 논문 그림 | 오픈 액세스(CC BY)면 출처 표시 후 사용. 그 외에는 다시 그리거나 쓰지 않는다 |

쓰지 않는 것: 검색 결과에서 출처 모르는 이미지, 언론사·통신사 사진(허락 없이), 워터마크 있는 이미지, 타사 제품 사진·로고(사용자가 허락을 확인해 준 경우만), 생성 이미지로 실물을 대신하는 것.

절차:
1. 장마다 필요한 사진을 스토리라인의 "화면" 열에 적는다(무엇이 보여야 하나).
2. 후보를 장당 2–3개 받아 `assets/candidates/`에 두고, 후보를 한 장에 모은 시트(PNG)를 만들어 사용자에게 보여 준다.
3. 사용자가 고른 것만 `assets/`로 옮기고 SOURCES.md에 적는다.
4. 슬라이드 출처 줄에 "Photo: 저작자/기관" 형식으로 적는다.
5. 해상도를 확인한다. 전면 사진은 가로 1920px 이상, 분할형은 세로 1080px 이상.

맞는 사진을 못 찾으면 억지로 넣지 않는다. 사용자에게 "이런 사진이 있으면 달라"고 구체적으로 요구하거나, 사진 없는 구성(큰 문장, 도형 그림)으로 바꾼다.

## 4. SOURCES.md 형식

```markdown
| 파일 | 내용 | 원본 (URL 또는 받은 경로) | 저작자·기관 | 라이선스·사용 조건 | 받은 날짜 | 쓰는 장 |
|---|---|---|---|---|---|---|
| photos/site_overview.jpg | 현장 전경 | 사용자 제공 | (촬영자) | 자사 소유 | 2026-11-12 | 1, 12 |
| ext/iss_plant.jpg | 궤도 재배 실험 | https://... | NASA | 공개 이미지, 출처 표시 | 2026-11-12 | 3 |
```
