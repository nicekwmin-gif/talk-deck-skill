# 최종 검토 체크리스트

최종 빌드 직전에 슬라이드(렌더 PNG)와 노트를 함께 읽는다. 지적은 목록으로 모았다가 한 번에 반영한다.
반영 결과는 표(위치 · 수정 · 이유)로 보고한다.

## 1. 주장 강도 (가장 자주 걸린다)

데이터가 말하는 만큼만 쓴다.

| 데이터가 말하는 것 | 쓰면 안 되는 말 | 쓸 말 |
|---|---|---|
| 시험 조건 한 가지에서 나온 결과 | 어디서나 된다, 검증됐다 | 시험한 조건(…)에서 |
| 실험·시험 1회, 표본이 적음 | 입증했다 | 예비 결과, 첫 시험에서 |
| 두 값이 함께 움직였다(상관) | A가 B를 일으킨다 | A가 높을 때 B도 높았다 |
| 차이가 통계적으로 유의하지 않음, 오차 범위가 겹침 | 늘었다, 더 좋다 | 늘어나는 경향, 비슷한 수준 |
| 기능을 직접 검증하지 않음 | ~한다 | ~할 것으로 본다 / likely, may |
| 양을 쟀다 | 속도·흐름이 바뀌었다 | 양이 늘었다 |
| 조건이 다른 자료와의 비교 | N배 우수 | 조건을 밝히고 나란히 보여 주거나 화면에서 뺀다 |
| 가정한 사례, 계획, 협의 중 | 적용 사례, 도입 예정 | 적용하면 이렇게 쓸 수 있다 / 계획 / 협의 중 |
| 찾아본 범위에서 선례 없음 | 최초, 유일, 업계 최고 | 우리가 아는 범위에서 / To our knowledge |
| 아직 공개·출판 전 | 발표한, 출판된 | 준비 중인, 사내 자료 |

## 2. 청중 맞춤

- 청중에서 가장 깐깐할 사람을 한 명 정한다(실무 기술 책임자, 예산 결정권자, 해당 분야 심사위원).
- 그 사람이 물을 질문을 다섯 개 적는다. 단골: 조건이 뭐였나, 표본이 몇 개인가, 비교 기준이 공정한가, 우리 환경에서도 되나, 비용·기간은, 실패한 경우는.
- 슬라이드 문구가 그 질문에 걸리면 데이터 수준으로 낮춘다. 답은 노트나 백업 장에 둔다.
- 청중이 모를 약어·전문용어가 설명 없이 나오는 곳을 찾는다.

## 3. 일치 검사

- [ ] 슬라이드 수치 = 노트 수치 = 원자료 수치 (단위, 반올림, 평균 종류 포함)
- [ ] 사실 확인표에 없는 수치·인용이 슬라이드에 없음
- [ ] 한 개념에 한 단어 (같은 것을 두 이름으로 부르지 않음), 제품명·회사명 표기 통일
- [ ] 그래프의 축·범례·각주가 헤드라인과 맞음
- [ ] 출처 줄이 그림·사진·인용이 있는 모든 장에 있음
- [ ] 사진 캡션의 장소·날짜가 확인된 범위 안
- [ ] 클릭 애니메이션 순서 = 노트의 `[클릭]` 위치
- [ ] 대외 공개하면 안 되는 것(미공개 수치, 고객사 이름, 가격, 개인정보)이 없음. 불확실하면 사용자에게 묻는다
- [ ] 과장 표현 없음: 획기적, 혁신적, 놀라운, 완벽한, remarkable, groundbreaking, significant(통계 외)
- [ ] 노트 오타·중복 단어 없음
- [ ] 쪽번호 1..N 연속

## 4. 디자인 검사

- [ ] `design_system.md` 1절의 증상 11가지에 해당하는 장 없음
- [ ] 장당 40단어 이하(출처·눈금 제외), 글자 크기 4단계 이내, 강조색 한 개
- [ ] 헤드라인만 이어 읽어도 이야기가 통함
- [ ] 헤드라인·출처·쪽번호 위치가 모든 장에서 같음
- [ ] 글자 겹침·잘림, 상자 밖으로 넘친 글, 슬라이드 밖 도형 없음 (렌더 PNG로 확인)

## 5. 기술 검사

- [ ] 저장한 pptx가 python-pptx로 다시 열림: `Presentation(path)`; 슬라이드 수가 맞음
- [ ] 전체 렌더 후 overview 그리드로 흐름 확인, 고친 장은 원본 크기 PNG로 확인
- [ ] 노트가 모든 장에 있음, 초 합계가 발표 시간의 75–80%
- [ ] 파일명: 영문·밑줄·`vN.N`·`YYYYMMDD`, `final` 없음
- [ ] 발표 PC에서 사용자가 직접 볼 것을 보고에 적음: 글꼴, 클릭 애니메이션, 동영상, 화면 비율
